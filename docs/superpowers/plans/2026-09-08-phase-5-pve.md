# Phase 5 cooperative PvE implementation plan

**Goal:** Extend the existing authoritative two-player slice with five zombie archetypes, five waves, damage, downing, revive, defeat and completion.

**Architecture:** Keep the existing Three.js client, Rapier player controller, Node WebSocket authority and shared Zod protocol. Compose bounded server systems; use a deterministic navigation grid from versioned simplified arena geometry. React continues to receive HUD samples at 10 Hz.

**Tech stack:** Installed Next 16.3.4, React 19.2.8, Three 0.185.1, Rapier 0.20.0, ws 8.21.3, Zod 4.5.4, TypeScript 5.9.3, Vitest and Playwright. No additional dependency.

## Constraints and pre-flight

- Phase 5 only. No shops, economy, extra weapons, upgrades, bosses, objectives, rewards, progression, leaderboards, chat or voice chat. No commits.
- Read root AGENTS.md, current Next client-component/CSS guides, Phase 4 architecture/operations and all gameplay, collision, reservation, reconnect, rendering and test boundaries.
- This checkout has no Git metadata. Preserve a source baseline and compare file hashes; do not infer that existing files are clean.
- Default npm and PowerShell module loading are broken. Use the installed Node npm CLI directly and Node filesystem APIs; record tooling repairs and failed checks.
- Use source-controlled validated tuning. Intermission restores starter rifle reserve to at least its initial reserve, without filling the magazine; reconnect never grants ammunition. This prevents an ammunition dead end across five waves without adding an item/economy system.
